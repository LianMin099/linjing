# 邻境：第一步操作指南

当前阶段：数据来源验证。现在还不是完整参赛系统。

## 今天完成一件事

验证你自己的高德 Web 服务 Key 能否查到学校以及附近银行、小区，并检查字段是否充足。

1. 打开高德官方申请说明：https://lbs.amap.com/api/webservice/create-project-and-key
2. 注册、登录开发者账号，按平台要求完成认证。
3. 在“应用管理 / 我的应用”创建应用，名称可以填“邻境”。
4. 添加 Key，服务平台选 **Web 服务**。此阶段不是 Web 端（JS API）。核实账号的服务权限、调用配额与费用；本工具不会购买服务。
5. 双击本文件夹的 `开始验证.cmd`。
6. 在黑色窗口中粘贴 Key 并按回车。输入时不显示字符，这是正常现象。Key 只留在本次进程内存中，不写入文件。
7. 工具展示学校搜索候选。核对名称、地址，选择龙翔大道 2188 号对应的学校主体。没有正确结果就输入 0 退出，不要选附近商铺或校门冒充学校中心。
8. 工具以所选点为中心，查询直线距离 3 公里范围的银行和小区，各取第一页最多 10 条。成功后查看 `reports` 文件夹内的报告。
9. 告诉 Codex“验证完成”或报告中的错误码即可，不要发送 Key。

如双击后无法启动，把窗口中的报错文字告诉 Codex。当前启动器使用已检查存在的 D:\python\python.exe；换电脑时需要调整。

## 今天需要学会的四个概念

- API：程序向其他服务查询数据的入口，类似有固定格式的办事窗口。
- Key：服务识别调用者的凭证，类似门禁卡。不要上传仓库或展示在比赛截图中。
- JSON：接口返回数据的结构。对象包含字段，例如名称、地址；列表包含多条对象。
- 可行性验证：用实际运行结果证明一条路线能走通，同时记录它做不到的部分。

可以打开 `probe_amap.py` 看三个关键函数：`request_api` 负责请求，`choose_school` 负责核对学校，`summarize` 负责统计返回字段。现在先理解流程，不要求背代码。

## 这次验证的边界

- 最多三个请求：学校关键词查询一次、银行周边查询一次、小区周边查询一次。不自动翻页，不自动重试。
- 报告只保存调用状态、样本数量与字段覆盖统计，不保存 Key、完整请求地址或原始地点列表。
- 查询属于候选数据源验证，不代表已取得批量采集、存储、版本管理或再次发布数据的授权。
- 接口返回空列表是有效结果，但不证明该区域没有地点；错误码也不能伪装成成功。
- 小区建成年代、住宅均价、物业费仍需要独立真实来源。接口中的 `cost` 是人均消费，不能当住宅均价。
- 第一页样本不能代表全部地点，字段覆盖率只针对本次样本。

完成后，下一步将根据真实结果确定数据源和存储方案，再实现采集、查询、纠错闭环。
